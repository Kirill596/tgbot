# Проверка версии без обязательного Google

Дата: 28.09.2026. Windows, Python 3.12.14, PostgreSQL 16.15.

**36 тестов на настоящем временном PostgreSQL прошли. Ruff: ошибок нет.**

## Исправление 28.09.2026: навигация и задержки

- Добавлена миграция `0002`: PostgreSQL хранит ID текущего экранного сообщения пользователя.
- Ответы на inline-кнопки теперь редактируют сообщение, на котором нажата кнопка. Очередь UI coalesces несколько изменений в одном update в один экран.
- Изолированная проверка отправки/редактирования прошла: первый экран отправлен один раз, следующий отредактировал тот же `message_id`.
- Отправка UI вынесена из обработки update в фоновую очередь; callback подтверждается до ожидания Telegram API.
- Для исходящих сообщений установлен 12-секундный сетевой тайм-аут. Long polling имеет отдельный 35-секундный тайм-аут, чтобы не обрываться раньше 25-секундного ожидания Telegram.
- Процесс после исправления работал 30 секунд без `polling_retry`; health-check отвечает успешно, миграция — `0002 (head)`.
- Убрана общая блокировка очереди: два независимых исходящих сообщения теперь обрабатываются параллельно. Изолированная проверка с намеренно медленным первым сообщением прошла за 2.04 секунды — второй аккаунт не ждал завершения первого.

## Запуск без Google

Отдельный процесс Python запущен в каталоге с `.env`, содержащим только BOT_TOKEN, ADMIN_ID=1132113524 и DATABASE_URL. Google-переменные отсутствовали. Импорт google, googleapiclient, google_auth_httplib2 и httplib2 намеренно блокировался: тест не мог незаметно воспользоваться установленными библиотеками.

Проверены реальные загрузка приложения, первичная загрузка городов/оффера, HTTP-сервер, внутренний планировщик и polling-цикл. Тестовое сообщение Start обработано, пользователь и источник сохранены в PostgreSQL. `/health` отвечает 200. В локальном polling-режиме `/telegram` недоступен (404), поэтому пустой вебхук-секрет не открывает вход для поддельных updates. Модуль Google Sheets рабочим процессом не загружен.

Telegram API в этой проверке подменён: настоящий BOT_TOKEN владельца не передавался. Это проверка запуска и обработки с реальной БД, а не отправка сообщений живому Telegram-боту.

## Перед настоящим запуском

Заполните три параметра `.env` и выполните контрольную заявку своим ботом по README. Облачный аккаунт не создавался, живой деплой без ключей владельца не выполнялся. Бесплатные условия Render и cron-job.org перепроверены по официальной документации; ограничения описаны в README.

Одна реплика сервера. Для точного учёта переходов по внешней ссылке нужен PUBLIC_URL; локальный прямой URL Telegram не присылает события клика. PostgreSQL остаётся единственным основным хранилищем всех рабочих данных. Делайте резервные копии БД.
