# Смена рядом — без Google Таблиц

Бот полностью работает с PostgreSQL. Google API, аккаунт Google и Google credentials не нужны. Заявки, персональные данные, прогресс анкеты, история статусов, события, напоминания и переходы к партнёру сохраняются в PostgreSQL. Админ-панель находится в Telegram и доступна только ID **1132113524**.

## Поведение экранов

При нажатии inline-кнопки бот обновляет это же сообщение: старый текст и кнопки заменяются новыми. Чат не превращается в ленту экранов. Сообщения, которые пользователь вводит сам, Telegram оставляет в истории — бот не может надёжно удалять их в личном чате. При шаге с запросом номера Telegram может создать один новый экран, чтобы показать системную кнопку передачи контакта; предыдущий экран при этом удаляется.

## Запуск на Windows: 5 шагов

**1. Создайте бота.** Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, укажите имя «Смена рядом» и свободный username с окончанием `bot`. Сохраните выданный токен.

**2. Создайте БД.** Зарегистрируйтесь в [Neon](https://neon.com/), создайте проект на тарифе **Free**. Нажмите **Connect**, отключите Connection pooling и скопируйте строку PostgreSQL. В ней замените `postgresql://` на `postgresql+asyncpg://`, `sslmode=require` на `ssl=require`. Если есть `&channel_binding=require`, удалите этот параметр. Пример структуры:

```dotenv
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST/neondb?ssl=require
```

Используйте готовый пароль из строки Connect, не меняя его кодирование.

**3. Заполните настройки.** Распакуйте архив. Скопируйте `.env.example` в `.env` и откройте Блокнотом. Нужны только три строки:

```dotenv
BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
ADMIN_ID=1132113524
DATABASE_URL=СТРОКА_ИЗ_NEON
```

Никаких GOOGLE_SHEET_ID и GOOGLE_CREDENTIALS. Не публикуйте `.env` и не отправляйте токен посторонним.

**4. Запустите.** Установите [Python 3.12](https://www.python.org/downloads/) с Python Launcher и галочкой **Add Python to PATH**. Дважды нажмите **start-windows.cmd**. Скрипт создаст окружение, установит зависимости без Google, применит миграции и запустит бота. Если `.env` ещё нет, откроется Блокнот: заполните настройки, сохраните и запустите файл ещё раз.

Пока бот работает локально, окно должно оставаться открытым, а компьютер — включённым. Остановка: Ctrl+C.

Если удобнее вручную, откройте PowerShell в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.main
```

Повторный запуск — последняя команда. Активировать окружение и менять ExecutionPolicy не требуется. Города и первая вакансия создаются автоматически, существующие данные сохраняются.

**5. Проверьте.** Откройте бота со своего аккаунта **1132113524** и нажмите Start — иначе бот не сможет присылать уведомления администратору. Главное меню → Панель администратора. Вакансии → Партнёрская ссылка → отправьте настоящую HTTPS-ссылку оформления. С другого аккаунта заполните тестовую анкету и проверьте уведомление.

## Админ-панель Telegram

Доступны: **Новые заявки**, **Все заявки**, данные кандидатов, **Договор заключён**, **В ожидании**, **Отказ**, статистика, источники, комментарии и контакт кандидата. Имя/ФИО, возраст, телефон, город и район показываются в карточке заявки. Статусы и история изменений сохраняются сразу в PostgreSQL, без синхронизации.

Обычным пользователям панель не показывается. Каждый административный обработчик проверяет ID; подделка callback и номера чужой заявки не дают доступ к данным. Настройки этой версии отклоняют ADMIN_ID, отличный от 1132113524. Административные операции в группах не обслуживаются.

## Бесплатный деплой: без включённого компьютера

Связка: **Render Free Web Service + Neon Free + cron-job.org**. Google не нужен. Бесплатный вариант имеет сон сервера и квоты, поэтому не гарантирует доступность 24/7.

1. Создайте приватный репозиторий [GitHub](https://github.com/) и загрузите содержимое папки проекта. Не загружайте `.env`, `.venv`, ключи и тестовые базы.
2. В [Render](https://render.com/) выберите **New → Web Service**, подключите репозиторий. Runtime **Docker**, тариф **Free**, Health check `/health`. Команды запуска и миграций уже в Dockerfile.
3. В Environment добавьте параметры:

| Параметр | Значение |
|---|---|
| BOT_TOKEN | Токен BotFather |
| ADMIN_ID | 1132113524 |
| DATABASE_URL | Та же строка Neon |
| MODE | webhook |
| SCHEDULER_MODE | external |
| PUBLIC_URL | HTTPS-адрес сервиса Render без `/` в конце |
| PORT | 8080 |
| WEBHOOK_SECRET | Первая случайная строка |
| CRON_SECRET | Вторая случайная строка |
| LINK_SECRET | Третья случайная строка |

Дополнительные параметры нужны именно публичному серверу для защиты вебхука, планировщика и ссылок. Для локального запуска их заполнять не нужно. Создать три разных секрета:

```powershell
py -3.12 -c "import secrets; print(secrets.token_urlsafe(32)); print(secrets.token_urlsafe(32)); print(secrets.token_urlsafe(32))"
```

4. Нажмите Deploy. Если PUBLIC_URL ещё не был указан, вставьте адрес из Render и повторите Deploy. Бот сам подключит вебхук. Перед этим остановите локального бота: один токен — один экземпляр сервера.
5. В [cron-job.org](https://cron-job.org/) создайте задание: URL `https://ВАШ-СЕРВИС.onrender.com/jobs/tick`, метод **POST**, каждые **30 минут**. Заголовок **Authorization**: `Bearer ВАШ_CRON_SECRET`. Включите уведомления о сбоях.
6. Нажмите Test run. Если сервер только просыпается, дождитесь запуска и повторите тест. Проверьте заявку в Telegram и уведомление администратора.

Вместо ручного создания можно выбрать **New → Blueprint**: `render.yaml` уже готов, не запрашивает Google и генерирует секреты. CRON_SECRET возьмите в Environment и вставьте в cron-job.org.

### Ограничения бесплатного тарифа

Render Free засыпает после 15 минут без запросов, пробуждение может занимать около минуты. У сервиса есть месячные квоты; сама платформа не рекомендует Free для production. Бесплатная БД Render истекает через 30 дней, поэтому здесь используется Neon. [Условия Render](https://render.com/docs/free).

Neon Free имеет ограничения объёма, вычислений и трафика; следите за лимитами в кабинете. Health-check бота не обращается к БД, чтобы не удерживать её активной. [Тариф Neon](https://neon.com/pricing).

cron-job.org бесплатен и поддерживает POST/заголовки, но ждёт ответ до 30 секунд — холодный старт может дать временную ошибку. Напоминания остаются в PostgreSQL до успешного вызова. [Правила cron-job.org](https://cron-job.org/en/faq/).

Точность follow-up — интервал планировщика плюс возможный простой. Для сервера без сна установите `SCHEDULER_MODE=internal` и отключите внешний cron: задачи проверяются каждые 30 секунд. Используйте одну реплику.

## Где сохраняются данные

| Данные | Таблица PostgreSQL |
|---|---|
| Пользователь, Telegram ID, username, первый/последний источник, кампания, активность | users |
| Имя/ФИО, возраст, телефон, город, район, готовность, опыт | applications.answers — JSON в PostgreSQL |
| Вакансия, партнёр, статус, шаг анкеты, дата заявки, согласие | applications |
| История статусов и автор изменения | status_history |
| События и воронка | events |
| Расписание, отправка и результаты напоминаний | reminders |
| Переход к партнёру | applications.clicked_at и PARTNER_LINK_CLICK в events |
| Вакансии и города | offers, cities |
| Обработанные Telegram updates и исходящие сообщения | update_receipts, outbox |

Схема базы не меняется: обновление сохраняет существующие данные. Не удаляйте PostgreSQL при замене файлов проекта.

## Учёт переходов к партнёру

На облачном сервере с PUBLIC_URL кнопка ведёт через подписанную страницу «Смена рядом». Нажатие «Перейти к оформлению» записывает событие в PostgreSQL и переводит на сайт партнёра. Предпросмотр ссылки не считается кликом.

Локально без публичного адреса работает прямая ссылка. Telegram не сообщает боту о нажатии обычной URL-кнопки: точную аналитику таких кликов получить нельзя. Для неё нужен публичный сервер, описанный выше. Анкета, заявки, админ-панель и напоминания работают локально.

## Настройки вакансий без таблиц

В Telegram можно включать/выключать вакансии и города, менять партнёрскую ссылку. Для новых городов, вакансий и изменения текстов редактируйте `config/catalog.json`. Идентификаторы — 1–24 латинских символа, цифры, `_` или `-`; в cities указывайте ID городов. Условия и суммы заполните реальными данными.

Применить каталог к БД:

```powershell
.\.venv\Scripts\python.exe -m app.cli catalog
```

Эта явная команда обновляет поля существующих офферов/городов из файла, включая active и partner_url, и добавляет новые. Поэтому перед командой сохраните в файле нужные значения, изменённые через Telegram. Пользователи и заявки не затрагиваются. Можно выполнить её с Windows, подключившись к той же Neon: консоль Render не нужна. Обычный перезапуск существующие настройки не перезаписывает. Для выключения используйте active=false.

## Напоминания и рекламные ссылки

Для проверки начните анкету тестовым аккаунтом, выберите город и остановитесь. В дневное время:

```powershell
.\.venv\Scripts\python.exe -m app.cli test-reminder --user 1132113524
```

Подставьте ID тестового аккаунта. Команда переносит ожидающее напоминание на сейчас, сохраняя дневное окно, паузу между отправками и запрет напоминаний. Локально дождитесь 30 секунд, в облаке вызовите cron. Кнопка «Продолжить» восстанавливает шаг. Повторные вызовы не дублируют тот же reminder.

«Не напоминать» отключает автоматические сообщения. Закрытые статусы прекращают follow-up. Известный город: 10:00–20:00 местного времени; неизвестный пояс: 08:00–09:00 UTC. Расширенные задержки и необязательные SUPPORT_URL/PRIVACY_URL/CONSENT_TEXT показаны в `.env.advanced.example`; для первого запуска копировать их не нужно.

REMINDER_OPEN означает нажатие кнопки, не чтение. Заявка связывается с последним таким нажатием в течение 7 дней. При неопределённом результате сетевой отправки сообщение получает unknown и не повторяется автоматически: это защита от дублей при аварии, возможен пропуск сообщения.

Рекламные ссылки:

```text
https://t.me/ВАШ_БОТ?start=avito_moscow_01
https://t.me/ВАШ_БОТ?start=avito_cheboksary_02
https://t.me/ВАШ_БОТ?start=vk_moscow_01
https://t.me/ВАШ_БОТ?start=tg_channel_01
```

Обычный Start не стирает источник. Статистика и разрезы доступны в Telegram. Периоды — UTC, метрики отражают события периода, а не когорты пользователей.

## Обновление старой версии и необязательный Google-адаптер

Остановите старый процесс, замените файлы, сохраните свой `.env`. Google-переменные можно удалить. Выполните установку requirements.txt и alembic upgrade head, затем запустите бота. Базу не удаляйте.

`app/google_sheets.py` оставлен для будущего ручного экспорта. Основной процесс его не импортирует и не запускает, кнопки синхронизации нет. Старые Google-переменные сами по себе ничего не включают. Только при отдельном решении в будущем можно установить requirements-google.txt, настроить ключи и вызвать `python -m app.cli sync`. Сейчас этого делать не нужно.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
```

TEST_DATABASE_URL позволяет прогнать проверки на отдельной PostgreSQL с именем smena_test. Тесты очищают эту тестовую БД, не указывайте рабочую базу кандидатов. Результаты поставленной версии — TEST_REPORT.md. В автоматических проверках Telegram подменяется, реальные сообщения требуют вашего BOT_TOKEN. Делайте резервные копии БД и не включайте debug-логи с персональными данными.
